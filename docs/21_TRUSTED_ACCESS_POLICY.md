# Codex 可信访问与执行边界

## 1. 目的

本策略确保 Codex 可以自主完成本地开发和验证，同时不会因为模糊授权触碰真实凭据、生产数据、外部发布或不可恢复操作。

## 2. 默认允许

- 读取本仓库源码、文档、测试和本地配置样例。
- 创建/修改任务范围内的源码、测试、文档和可恢复构建产物。
- 安装 lockfile 固定的依赖，运行类型检查、测试、构建、Benchmark 和本地容器。
- 查询公开官方文档、Release、License 和漏洞公告。
- 使用虚构/脱敏 Fixture 和本地测试数据库。
- 生成 ZIP、Manifest、Checksum 和验收证据。

## 3. 必须获得明确授权

- Push、PR、Release、镜像发布和外部站点部署。
- 连接生产/预生产数据库、云账号、真实对象存储或消息队列。
- 创建、旋转、导出或复用真实凭据和 Secret。
- 删除数据库、存储桶、远程分支、部署或其他重要资源。
- 向外部人员发送消息、邀请、邮件或审批。
- 处理未脱敏的真实位置、人员轨迹或租户业务数据。

授权必须包含具体目标、环境和操作，不能由“继续”“部署一下”等模糊词自动扩大。

## 4. 永远禁止

- 绕过权限、认证、审计、安全扫描或测试门禁。
- 在日志、错误、文档、命令输出或交付包中暴露凭据。
- 把 `.env`、密钥、Token、数据库备份或真实用户轨迹打入 ZIP。
- 因环境缺失而伪造 Docker、数据库、浏览器或生产测试结果。
- 使用破坏性命令清理不明确的目录或用户已有改动。

## 5. 数据分级

| 级别 | 示例 | 处理规则 |
|---|---|---|
| Public | H3 官方文档、开源代码 | 可公开检索和引用 |
| Internal | 设计、测试、虚构 Fixture | 仅任务范围内使用 |
| Sensitive | 精确车辆/人员轨迹、租户 Geometry | 最小化、脱敏、限制保存和输出 |
| Secret | 密钥、Token、连接口令 | 只通过 Secret 系统注入，不读取或回显 |

H3 Cell 仍可能反推出大致位置，不能因为它不是经纬度就自动降为非敏感数据。

## 6. 外部依赖原则

- 优先官方/主仓库/标准文档。
- 固定版本和 lockfile，升级前检查 Release、API 兼容、License 和漏洞。
- 生产镜像使用 digest、SBOM、扫描和签名。
- 不把临时网络失败当作授权去寻找非可信镜像或绕过校验。

## 7. 阻塞处理

遇到权限、凭据、生产目标、数据敏感性或破坏性操作不清楚时：

1. 停止相关操作。
2. 保留已完成的本地可恢复工作。
3. 说明缺少的具体授权或环境。
4. 提供安全的本地验证替代方案。
5. 等待用户明确选择后继续。
